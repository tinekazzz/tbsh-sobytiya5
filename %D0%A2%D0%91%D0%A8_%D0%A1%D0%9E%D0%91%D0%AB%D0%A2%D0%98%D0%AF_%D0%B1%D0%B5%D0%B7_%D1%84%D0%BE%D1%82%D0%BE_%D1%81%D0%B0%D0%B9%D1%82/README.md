# ТБШ СОБЫТИЯ

**Редакторская афиша культурных событий Москвы и России с ежедневным обновлением.**

В комплекте: сайт, справочник из **241 источника** и **332 имен**, 19 проверенных стартовых анонсов, поисковые фильтры, избранное, CSV-экспорт и запланированный ежедневный сборщик из открытых официальных страниц.

> Статус на момент передачи: сайт и планировщик подготовлены, но **не опубликованы в интернете**. Пока GitHub Actions не запущен, события не обновляются автоматически. Доступ к каждому из 241 сайта не проверен, 11 официальных площадок настроены как стартовые кандидаты для автоматического сбора.

## Фирменный стиль

Дизайн переоформлен по материалам ТБШ: чёрный, белый, электрический синий, крупная контрастная типографика и оригинальная эмблема с предоставленного пользователем изображения. Главный баннер показывает название следующего месяца, переключение работает вместе с афишей. Логика сайта, источники, поиск, избранное и ежедневный сборщик остались прежними.

## Что работает на сайте

- Афиша выбранного месяца, по умолчанию следующего календарного.
- «Обзор», «Новые находки», «Избранное», «Источники», «Имена», «Как это работает».
- Поиск по событиям и площадкам, фильтр по жанрам и регионам, сортировка по дате/интересу/моменту добавления.
- Карточки с датами, площадкой, описанием, участниками и ссылкой на первоисточник.
- Сохранение избранного **в текущем браузере** и выгрузка CSV для сценария ролика.
- Видимый статус последней автоматической проверки источников.
- Используемая подборка источников взята из `registry/full_registry.json`.

## Запустить на своём компьютере

```bash
cd site
python3 -m http.server 8000
```

Открыть `http://localhost:8000/`. Для быстрого просмотра без локального сервера используйте приложенный отдельно файл `ТБШ_СОБЫТИЯ_превью.html` — он самодостаточный, но **не умеет автоматически обновлять сведения**.

## Опубликовать с ежедневным обновлением через GitHub Pages

1. Создать репозиторий в GitHub и загрузить **содержимое этой папки**, включая скрытую `.github`.
2. Открыть **Settings → Pages → Build and deployment → Source → GitHub Actions**.
3. В разделе **Actions** разрешить запуск workflows при необходимости. При ограничениях на запись также разрешить GitHub Actions создание коммитов в ветку `main`.
4. Запустить вручную workflow **Daily culture radar update and publish** кнопкой **Run workflow**. Затем он будет запускаться каждый день около **06:20 МСК**.
5. Открыть ссылку на сайт в **Settings → Pages**; обычно это `https://USERNAME.github.io/REPOSITORY/`.

Workflow: `.github/workflows/daily-update.yml`. Он проверяет поддерживаемые страницы, пытается найти новые события с **подтверждаемой датой** и сохраняет `site/data/events.json` и `site/data/status.json`, затем разворачивает сайт. `schedule` GitHub Actions может запускаться с задержкой; в неактивных открытых репозиториях GitHub может отключить расписание.

## Как добавлять источники

- Полный реестр: `registry/full_registry.json`.
- Источники в интерфейсе: `site/data/sources.json`.
- Реально запрашиваемые адреса: `pipeline/collectors.json` (включённые записи с `enabled: true`).
- Имена для поиска: `site/data/people.json`.
- Проверенные редакцией события: `site/data/editorial_events.json`.

Чтобы добавить сайт к сбору, добавьте его с корректным официальным URL в `pipeline/collectors.json`, проверьте robots.txt, HTML/JSON-LD и условия использования. `source_id` должен соответствовать ID в `site/data/sources.json`. **Наличие в справочнике не означает, что парсер уже подключён.**

Для добавления события вручную поместите запись в `site/data/editorial_events.json` по образцу, затем запустите сборщик. Минимальные поля: `id`, `title`, `start_date` (`YYYY-MM-DD`), `end_date`, `category`, `city`, `venue`, `url` (официальный HTTPS), `description`, `source_name`. Новые записи видны после публикации обновлённого файла.

### Локальный тест сборщика

```bash
pip install -r pipeline/requirements.txt
python pipeline/update_events.py --offline   # без интернета, с редакционными анонсами
python pipeline/update_events.py             # реальный сбор при доступной сети
python -m pytest -q tests
```

## Как устроен поиск

1. Скрипт посещает ограниченный список официальных страниц и проверяет `robots.txt`.
2. Ищет структурированную разметку `schema.org/Event` (JSON-LD). Для некоторых сайтов также ищет даты в `time` и рядом с конкретными ссылками на событие.
3. Если дата не подтверждена или не относится к предстоящим месяцам, запись отбрасывается.
4. События приводятся к общей структуре, сопоставляются с известными именами и удаляются очевидные дубли.
5. Стартовые редакторские карточки сохраняются, но прошлые мероприятия автоматически пропадают из выборки. Веб-страница показывает только события выбранного месяца с учётом длительных выставок.

### Важно: ограничения

- Это **первый технический MVP**, а не обещание полного сбора с 241 площадки. Часть страниц формируется только JavaScript, не содержит событий в JSON-LD, блокирует роботов или не предоставляет открытый доступ. Для таких источников нужны отдельные разрешённые интеграции, адаптеры либо ручная редактура.
- Открытый API KudaGo больше не доступен; официальная культурная база PRO.Культура.РФ требует партнёрский ключ. Проект намеренно не использует недействующие обходные API.
- Система не выдаёт «открыто сегодня» и не гарантирует наличие билетов. Данные из официальной афиши меняются — всё проверяется у организатора.
- Поиск по фамилиям выполняется **по тексту реально обнаруженных событий**. Это ещё не отдельный автоматический веб-поиск по 332 именам. Для расширения покрытия потребуются официальные поисковые API/индексация.
- Для полного редакционного цикла в дальнейшем имеет смысл подключить хранилище, модерацию карточек, роли редакторов, источник фото и уведомления по новым находкам. Пока избранное локально для каждого браузера.

## Структура проекта

```text
site/
  index.html                   страница сайта
  assets/app.css              стили
  assets/app.js               логика интерфейса
  data/events.json            события для показа
  data/status.json            статус последнего запуска
  data/editorial_events.json  проверенные редакторские записи
  data/sources.json           241 источник
  data/people.json            332 имени
pipeline/
  collectors.json             11 пилотных сайтов для парсинга
  update_events.py            сбор, фильтрация, объединение, сохранение
  seed_data.py                воспроизводимая стартовая подборка
.github/workflows/
  daily-update.yml            ежедневный запуск и публикация GitHub Pages
registry/full_registry.json   исходный реестр
```

## Лицензии и использование

Не копируйте без разрешения чужие изображения и полные описания. Указывайте первоисточник, показывайте собственные короткие редакционные описания и соблюдайте правила сайта. Доступ к платным API оформляйте отдельно. Данные носят информационный характер.
